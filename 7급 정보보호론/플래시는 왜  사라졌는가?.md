

# 1. 플래시(Flash)

## 1-1. 개념

플래시는 웹 브라우저에서
애니메이션, 동영상, 게임, 인터랙티브 콘텐츠를 실행하기 위한
**플러그인 기반 멀티미디어 기술**이다.

브라우저 자체 기능이 아니라
**Flash Player라는 외부 실행 모듈**에 의존한다.

---

## 1-2. 구성 요소

| 구성 요소        | 설명              |
| ------------ | --------------- |
| Flash Player | 플래시 콘텐츠 실행 환경이다 |
| SWF 파일       | 플래시 실행 파일 형식이다  |
| ActionScript | 플래시용 스크립트 언어이다  |

---

## 1-3. 실제 사용 예시

* 웹사이트 인트로 애니메이션
* 웹 게임
* 광고 배너
* 과거 동영상 스트리밍 서비스

---

# 2. Flash MX

## 2-1. 개념

Flash MX는
**플래시 콘텐츠를 제작하기 위한 저작 도구(IDE)**이다.

플래시 기술 자체가 아니라
**플래시 파일(SWF)을 만드는 프로그램**이다.

---

## 2-2. MX의 의미

MX는 **Media eXtension**이다.
멀티미디어 제작 기능을 확장한 버전이라는 의미이다.

---

## 2-3. 주요 기능

| 기능           | 설명                  |
| ------------ | ------------------- |
| 타임라인         | 프레임 기반 애니메이션 제작     |
| 벡터 그래픽       | 용량 대비 고화질 표현        |
| ActionScript | 로직 및 이벤트 처리         |
| SWF 출력       | Flash Player용 파일 생성 |

---

## 2-4. 실제 사용 예시

* 웹 디자이너의 인트로 페이지 제작
* 교육용 멀티미디어 콘텐츠
* 플래시 게임 제작

---

## 2-5. Flash MX의 한계

Flash MX로 만든 결과물은
**Flash Player가 없으면 실행 불가**이다.

플래시 기술이 퇴출되면서
Flash MX도 함께 사라졌다.

---

# 3. 플래시의 구조적 보안 문제 (핵심)

플래시는 단순히 버그가 많은 수준이 아니라
**구조 자체가 현대 웹 보안 모델과 충돌**했다.

---

## 3-1. 브라우저 외부 실행 구조

### 개념

플래시는 브라우저 내부가 아닌
**외부 플러그인으로 실행**된다.

브라우저 → 플래시 플레이어 → 운영체제
라는 구조이다.

### 보안 문제

* 브라우저 보안 정책 우회
* 동일 출처 정책 보호 약화
* 브라우저보다 넓은 권한 사용

### 실제 위험

플래시 취약점 하나로
브라우저를 넘어 OS 영역까지 침해 가능했다.

---

## 3-2. 메모리 직접 접근

### 개념

플래시는 C/C++ 기반 네이티브 코드로 구현되었다.
메모리를 직접 다룬다.

### 보안 문제

* 버퍼 오버플로우
* Use-After-Free
* 힙 오버플로우

같은 메모리 취약점이 빈번했다.

### 실제 위험

입력값 조작만으로
**원격 코드 실행(RCE)** 이 가능했다.

---

## 3-3. 샌드박스 취약

### 개념

샌드박스는
프로그램을 제한된 환경에서 실행하여
피해 확산을 막는 보안 기법이다.

### 플래시의 문제

* 자체 샌드박스가 불완전했다
* 브라우저·OS 샌드박스와 분리되어 있었다
* 샌드박스 탈출이 쉬웠다

### 결과

플래시 취약점 + 브라우저 취약점 연계로
시스템 전체 장악이 가능했다.

---

# 4. 플래시 보안 공격 방식

## 4-1. 제로데이 공격

* 공개되지 않은 취약점 이용
* 패치 전 공격 성공

예시
악성 SWF 파일 삽입
→ 접속만 해도 악성 코드 실행

---

## 4-2. 원격 코드 실행(RCE)

* 메모리 취약점 이용
* 공격자 코드 실행

예시
광고 배너에 악성 플래시 삽입
→ 사용자 PC 감염

---

## 4-3. 드라이브 바이 다운로드

* 사용자 클릭 없이 감염
* 웹페이지 로딩만으로 공격 성공

---

## 4-4. 권한 상승 공격

* 플래시 취약점 + OS 취약점 결합
* 관리자 권한 획득

---

# 5. 플래시가 공격자에게 매력적이었던 이유

* 설치율이 매우 높았다
* 자동 실행이 가능했다
* 취약점이 지속적으로 발견되었다
* 패치 속도가 공격 속도를 따라가지 못했다

공격자 입장에서
**가장 효율적인 공격 대상**이었다.

---

# 6. 플래시 vs Flash MX vs 보안 공격 종합 표

| 구분    | 플래시     | Flash MX | 보안 공격    |
| ----- | ------- | -------- | -------- |
| 성격    | 실행 기술   | 제작 도구    | 공격 기법    |
| 역할    | 콘텐츠 실행  | 콘텐츠 생성   | 시스템 침해   |
| 핵심 문제 | 플러그인 구조 | 플래시 의존   | 제로데이·RCE |
| 현재 상태 | 사용 불가   | 단종       | 역사적 사례   |

---

# 7. 최종 핵심 정리

* 플래시는 **웹 멀티미디어 실행 기술**이다
* Flash MX는 **플래시 콘텐츠 제작 도구**이다
* 플래시는 구조적으로 보안에 취약했다
* 제로데이와 RCE 공격의 주요 통로였다
* HTML5 등장과 함께 **보안상 퇴출**되었다

결론적으로
**플래시는 낡아서 사라진 것이 아니라, 위험해서 제거된 기술**이다.
