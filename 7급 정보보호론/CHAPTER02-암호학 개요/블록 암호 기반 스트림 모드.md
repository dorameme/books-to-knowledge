 **블록 암호와 스트림 암호는 원래 다른 개념**이다.      
다만 실무에서는 **블록 암호를 스트림 암호처럼 쓰는 방식**이 존재하고,      
그걸 **블록 암호 기반 스트림 모드**라고 부른다. 헷갈리기 쉬운 지점이라 정확히 정리한다.

---

## 1. 블록 암호와 스트림 암호의 근본적 차이

### 블록 암호

* 고정 길이 블록 단위로 암호화한다
* 예: 128비트 블록
* 같은 입력 블록은 같은 출력 블록이 된다
* 단독 사용 불가이며 반드시 운용 모드가 필요하다

### 스트림 암호

* 비트 또는 바이트 단위로 암호화한다
* 키 스트림을 생성해 XOR 연산을 수행한다
* 실시간 처리에 적합하다

---

## 2. 왜 블록 암호 기반 스트림 모드가 등장했는가

이유는 명확하다.

* 검증된 스트림 암호가 부족하다
* 블록 암호(AES)는 충분히 검증되었다
* 블록 암호 하나로 다양한 용도를 커버하고 싶었다
* 하드웨어·소프트웨어 구현 통일이 필요했다

그래서 **블록 암호를 키 스트림 생성기로 사용**하는 방식이 만들어졌다.

---

## 3. 블록 암호 기반 스트림 모드의 핵심 개념

핵심은 이것이다.

> 블록 암호를 “평문 암호화 도구”로 쓰지 않고
> **난수처럼 보이는 키 스트림 생성기**로 사용한다

### 동작 개념

1. 블록 암호에 특정 입력을 넣는다
2. 출력값을 키 스트림으로 사용한다
3. 키 스트림과 평문을 XOR한다
4. 결과가 암호문이다

즉, **AES는 블록 암호지만 결과적으로 전체 구조는 스트림 암호처럼 동작**한다.

---

## 4. 대표적인 블록 암호 기반 스트림 모드

### 1) CTR 모드

* 카운터 값을 AES에 입력한다
* 출력이 키 스트림이다
* 가장 전형적인 동기식 스트림 암호 구조이다

### 2) OFB 모드

* 이전 출력값을 다시 입력한다
* 자기동기식처럼 보이지만 구조적으로는 동기식이다

### 3) CFB 모드

* 이전 암호문을 입력으로 사용한다
* 자기동기식 스트림 암호에 해당한다

---

## 5. 구조 비교 표

| 구분       | 순수 스트림 암호  | 블록 암호 기반 스트림 모드  |
| -------- | ---------- | ---------------- |
| 기본 구성    | 키 스트림 생성기  | 블록 암호            |
| 키 스트림 생성 | 전용 알고리즘    | AES 등 블록 암호      |
| 암호화 방식   | 평문 ⊕ 키 스트림 | 평문 ⊕ 키 스트림       |
| 단위       | 비트/바이트     | 블록 출력 → 스트림      |
| 예시       | ChaCha20   | AES-CTR, AES-OFB |

---

## 6. 중요한 오해 정리

1. **AES-CTR은 블록 암호가 아니다**
   → AES는 블록 암호이고, CTR은 스트림 운용 방식이다

2. **블록 암호 기반 스트림 모드는 스트림 암호로 분류된다**
   → 동작 방식 기준이다

3. **블록 단위로 XOR하지 않는다**
   → 블록 출력 결과를 잘라 스트림처럼 XOR한다

---

## 7. 왜 실무에서는 이 방식을 쓰는가

* AES의 보안성이 이미 충분히 검증되었다
* 구현이 단순하고 빠르다
* 병렬화가 가능하다
* 스트림 암호의 장점을 그대로 얻는다

그래서 TLS, VPN, 디스크 암호화 등에서 널리 사용된다.

---

## 8. 한 줄 정리

블록 암호와 스트림 암호는 본질적으로 다르다.
블록 암호 기반 스트림 모드는 **블록 암호를 키 스트림 생성기로 사용해 스트림 암호처럼 동작하게 만든 방식**이다.

## 1. 안전한 스트림 암호가 부족했기 때문이다

과거에 쓰이던 스트림 암호들(RC4 등)은 시간이 지나면서 구조적 취약점이 드러났다.
반면 AES 같은 블록 암호는 수십 년간 분석되어도 깨지지 않았다.
그래서 **새 스트림 암호를 믿느니, 검증된 블록 암호를 재활용하는 선택**을 했다.

---

## 2. 블록 암호는 이미 표준이고 널리 깔려 있었다

* 하드웨어 가속이 있다
* 라이브러리와 구현이 풍부하다
* 인증, 표준, 검증이 끝나 있다

이 상황에서 스트림 암호를 따로 도입하는 건 비용과 위험이 크다.
그래서 **블록 암호 하나로 여러 운용 방식을 만들었다**.

---

## 3. 스트림 암호의 장점이 실제로 필요했기 때문이다

실무에서는 다음이 중요하다.

* 실시간 처리
* 병렬 처리
* 오류 전파 최소화

CTR 같은 모드는

* 패딩이 필요 없다
* 병렬 암·복호가 가능하다
* 비트 단위 오류만 발생한다

즉, **스트림 암호의 장점을 그대로 가져온다**.

---

## 4. 구조적으로 구현이 더 단순하다

블록 암호 기반 스트림 모드는 구조가 명확하다.

* 블록 암호 = 키 스트림 생성기
* XOR = 암호화의 전부

복호도 동일한 연산을 반복한다.
코드가 단순하고 실수할 여지가 적다.

---

## 5. 프로토콜 설계에 유리하다

TLS, IPsec 같은 프로토콜은 다음을 요구한다.

* 암호화
* 무결성
* 재전송
* 병렬성

CTR, GCM 같은 모드는 이런 요구사항과 잘 맞는다.
그래서 **프로토콜 레벨에서 채택되기 쉬웠다**.

---

## 6. 한 줄로 정리하면

스트림 암호가 필요했는데,     
새 스트림 암호를 믿기엔 위험했고,          
AES는 이미 충분히 믿을 수 있었기 때문에       
**블록 암호를 스트림 암호처럼 쓰는 방식이 표준이 되었다**.

----

## 왜 스트림암호가 필요했는가?
연속적이고 즉시 처리해야 하는 데이터가 많아졌기 때문이다.

---

## 1. 실시간 통신이 필요한 경우

### 왜 블록 암호가 불리한가

* 블록이 다 찰 때까지 기다려야 한다
* 패딩이 필요하다
* 지연(latency)이 발생한다

### 스트림 암호가 필요한 상황

* 입력이 끊임없이 들어온다
* 지금 들어온 데이터는 지금 암호화해야 한다

### 실제 사례

* 음성 통화
* 화상 회의
* 실시간 스트리밍

이런 경우 **스트림 단위 XOR 방식이 필수**이다.

---

## 2. 데이터 길이를 미리 알 수 없는 경우

### 문제

* 블록 암호는 고정 길이 단위를 전제로 한다
* 스트림처럼 끝이 언제 올지 모르는 데이터에 부적합하다

### 필요한 특성

* 바이트 단위 암호화
* 종료 시점 예측 불필요

### 실제 사례

* 소켓 통신
* 터널링(VPN)
* 장시간 유지되는 연결

CTR 같은 모드는 이 문제를 해결한다.

---

## 3. 고속·병렬 처리가 필요한 경우

### 블록 암호 단점

* CBC 같은 모드는 순차 처리 강제
* 병렬화가 어렵다

### 스트림 모드 장점

* 키 스트림 미리 생성 가능
* 병렬 암·복호 가능

### 실제 사례

* 대규모 서버
* CDN
* 고속 네트워크 장비

---

## 4. 오류 확산이 치명적인 경우

### 블록 암호 문제

* 블록 하나가 깨지면 다음 블록까지 영향이 간다

### 스트림 암호 필요성

* 오류는 해당 비트에서 끝나야 한다

### 실제 사례

* 무선 통신
* 위성 통신
* 이동 중 네트워크

---

## 5. 패딩이 문제되는 경우

### 블록 암호 문제

* 패딩 오라클 공격 가능성
* 구현 실수 빈번

### 스트림 암호 장점

* 패딩 자체가 없다
* 공격면이 줄어든다

### 실제 사례

* 보안 프로토콜
* 라이브러리 범용 제공

---

## 6. 요약 표

| 필요했던 상황   | 왜 스트림 암호가 필요했는가 |
| --------- | --------------- |
| 실시간 데이터   | 즉시 암호화가 필요했다    |
| 길이 미정 데이터 | 블록 단위가 맞지 않았다   |
| 고속 처리     | 병렬화가 필요했다       |
| 오류 민감 환경  | 오류 확산을 막아야 했다   |
| 보안 구현 안정성 | 패딩을 제거해야 했다     |

---

## 7. 한 문장 정리

블록 암호 기반 스트림 모드는
**실시간·연속·고속·오류 민감한 통신 환경에서 블록 암호가 맞지 않았기 때문에 등장했다**.
