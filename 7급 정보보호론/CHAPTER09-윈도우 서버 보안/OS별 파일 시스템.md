# 리눅스, 유닉스, 윈도우 파일 시스템 구조 비교

## 1. 리눅스 (Linux)

### 파일 시스템 구조
```
[부트 블록] → [슈퍼블록] → [블록 그룹 0] → [블록 그룹 1] → ...
```

**부트 블록**: 부트로더가 위치, 커널 이미지 로딩 담당  
**슈퍼블록**: 파일 시스템 전체 정보(블록 수, i-node 수, 상태, 마운트 정보)  
**i-node**: 파일별 메타데이터(권한, 소유자, 크기, 시간정보, 데이터 블록 위치)  
**주요 파일 시스템**: ext4(기본), XFS(대용량), Btrfs(고급 기능)

**특징**: 모듈형 설계, 서버/개발 최적화, 높은 자유도, 안정적 i-node 구조

---

## 2. 유닉스 (Unix)

### 파일 시스템 구조
```
[부트 블록] → [슈퍼블록] → [실린더 그룹 0] → [실린더 그룹 1] → ...
```

**부트 블록**: 초기 커널 로드 및 시스템 초기화  
**슈퍼블록**: 볼륨 정보, 블록/파일 수, 상태 플래그  
**i-node**: 파일 메타데이터 + 직접/간접 블록 포인터  
**주요 파일 시스템**: UFS(전통적), ZFS(고급), JFS(저널링)

**특징**: 전문가 중심, 검증된 안정성, 장기 운영 서버 적합, 실린더 그룹 최적화

---

## 3. 윈도우 (Windows)

### 파일 시스템 구조
```
[부트 섹터] → [MFT 영역] → [시스템 파일] → [사용자 데이터]
```

**부트 섹터**: 부트로더와 파티션 정보 포함  
**MFT(마스터 파일 테이블)**: 슈퍼블록+i-node 통합 역할  
**MFT 레코드**: 파일별 메타데이터, 속성, 데이터 위치(클러스터)  
**주요 파일 시스템**: NTFS(기본), FAT32(호환성), ReFS(서버용)

**특징**: GUI 통합 설계, 사용자 편의성, 기업 환경 최적화, B+ 트리 디렉토리

| **전체 관리** | 슈퍼블록 | 슈퍼블록 | MFT |
| **파일 관리** | i-node | i-node | MFT 레코드 |
| **메타데이터 저장** | 분리 구조 | 분리 구조 | 통합 구조 |

## 핵심 차이 요약

1. **아키텍처 철학**: 리눅스/유닉스는 모듈형 분리 설계, 윈도우는 통합 설계
2. **메타데이터 관리**: 리눅스/유닉스는 슈퍼블록+i-node 이중 구조, 윈도우는 MFT 단일 구조
3. **사용자 대상**: 리눅스=서버/개발자, 유닉스=전문가/기업, 윈도우=일반 사용자/기업
4. **파일 검색**: 리눅스=다양한 알고리즘, 유닉스=선형 검색, 윈도우=B+ 트리 인덱스
5. **하드웨어 연계**: 유닉스=특정 하드웨어 최적화, 리눅스=범용 하드웨어, 윈도우=x86/x64 최적화

## 적합한 사용 사례

- **리눅스 선택**: 웹 서버, 클라우드 인프라, 개발 환경, 비용 제약 프로젝트
- **유닉스 선택**: 금융시스템, 항공예약, 대규모 데이터베이스, SLA 중요 시스템  
- **윈도우 선택**: 데스크톱 환경, Active Directory, .NET 애플리케이션, 사무 자동화
