
## 1. 핵심 개념

* 여러 데이터(트랜잭션)를 해시로 묶어 하나의 대표 해시로 요약한다
* 이 대표 해시를 머클 루트(Merkle Root)라 한다
* 데이터 하나라도 바뀌면 루트 해시가 바뀐다

---

## 2. 왜 필요한가

* 블록에 수천 개 트랜잭션이 들어간다
* 전체를 다 확인하면 비효율적이다
* 머클 트리를 쓰면 일부 데이터만으로도 전체 무결성 검증이 가능하다

---

## 3. 구조

1. 각 트랜잭션 → 해시
2. 인접한 해시 2개를 묶어 다시 해시
3. 이를 반복해 최상단 하나의 해시 생성

```
Tx1  Tx2  Tx3  Tx4
 |    |    |    |
 h1   h2   h3   h4
   h12        h34
        h1234  ← Merkle Root
```

---

## 4. 검증 방식 (Merkle Proof)

* 특정 트랜잭션이 블록에 포함됐는지 확인할 때
* 해당 경로의 해시들만 있으면 검증 가능
* 전체 블록을 다운로드할 필요가 없다

→ SPV 노드가 가능해진다

---

## 5. 블록체인에서의 역할

| 역할     | 설명             |
| ------ | -------------- |
| 무결성 검증 | 데이터 위변조 즉시 탐지  |
| 효율성    | O(log N) 검증    |
| 경량 노드  | 전체 체인 없이 검증 가능 |
| 보안성    | 해시 충돌 어려움에 기반  |

---

## 6. 실제 사용 예

* 비트코인 블록의 트랜잭션 요약
* 이더리움의 상태 트리(머클 패트리시아 트리)
* Git의 커밋 구조
* 파일 무결성 검증 시스템

---

## 7. 한 줄 정리

> 머클 트리는 많은 데이터를 하나의 해시로 요약하면서, 일부 정보만으로도 전체 무결성을 증명하는 구조이다.
