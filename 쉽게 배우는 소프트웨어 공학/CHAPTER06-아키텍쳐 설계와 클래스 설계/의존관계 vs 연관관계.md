

## 1. 한 줄 정의

| 구분   | 정의                                   |
| ---- | ------------------------------------ |
| 연관관계 | 객체가 **서로를 멤버로 가지고 지속적으로 알고 있는 관계**이다 |
| 의존관계 | 객체가 **일시적으로 다른 객체를 사용만 하는 관계**이다     |

---

## 2. 가장 쉬운 구별 질문

> **“이 객체가 사라져도 저 객체는 계속 기억해야 하는가?”**

| 질문 결과      | 관계     |
| ---------- | ------ |
| 계속 기억해야 한다 | 연관관계이다 |
| 잠깐 쓰고 끝이다  | 의존관계이다 |

---

## 3. 코드로 바로 구별하는 예시

### 3-1. 연관관계 예시 (멤버 변수로 가진다)

```java
class Student {
    private School school;
}
```

* Student는 School을 **필드로 가진다**
* Student 객체가 살아 있는 동안 School을 안다
* **지속적 관계**이다

→ 연관관계이다

---

### 3-2. 의존관계 예시 (메서드에서만 쓴다)

```java
class Student {
    void register(School school) {
        school.addStudent(this);
    }
}
```

* School은 메서드 파라미터로만 등장한다
* 호출이 끝나면 관계도 끝난다
* **일시적 사용**이다

→ 의존관계이다

---

## 4. 실생활로 이해하는 초간단 비유

### 연관관계

* 사람 ↔ 핸드폰이다
* 항상 가지고 다닌다
* 없어지면 생활에 영향이 있다

→ **지속적 소유 관계**

---

### 의존관계

* 사람 ↔ 택시이다
* 탈 때만 필요하다
* 내 것이 아니다

→ **일시적 사용 관계**

---

## 5. UML 관점에서 차이

| 구분     | 연관관계     | 의존관계 |
| ------ | -------- | ---- |
| UML 표현 | 실선       | 점선   |
| 관계 강도  | 강하다      | 약하다  |
| 생명주기   | 오래 간다    | 짧다   |
| 필드 포함  | 있다       | 없다   |
| 결합도    | 상대적으로 높다 | 낮다   |

---

## 6. 실무에서 중요한 이유

* 연관관계가 많아질수록 **결합도가 높아진다**
* 의존관계로 설계할수록 **유연하고 테스트하기 쉽다**
* 스프링에서 말하는 **DI 핵심은 의존관계 관리**이다

---

## 7. 한 줄로 정리

* **필드로 들고 있으면 연관관계이다**
* **메서드에서 잠깐 쓰면 의존관계이다**
