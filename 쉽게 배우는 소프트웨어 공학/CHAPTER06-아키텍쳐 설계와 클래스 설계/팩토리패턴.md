## **팩토리 패턴 간단 정리**

**핵심 개념**: 객체 생성 로직을 캡슐화하여 클라이언트가 직접 `new`를 사용하지 않도록 하는 생성 패턴

**주요 목적**:
1. 객체 생성과 사용의 분리
2. 구체 클래스에 대한 의존성 제거
3. 유연한 객체 생성 메커니즘 제공

**패턴 종류**:
- **간단 팩토리**: 조건문 기반 단일 생성 메소드
- **팩토리 메소드**: 상속을 통한 객체 생성 위임
- **추상 팩토리**: 관련 객체 패밀리 생성 인터페이스

## **실무 예시**

### **1. 간단 팩토리 - 결제 수단 생성**
```java
public class PaymentFactory {
    public Payment createPayment(String type) {
        if ("CREDIT_CARD".equals(type)) return new CreditCardPayment();
        if ("BANK_TRANSFER".equals(type)) return new BankTransferPayment();
        if ("PAYPAL".equals(type)) return new PayPalPayment();
        if ("KAKAOPAY".equals(type)) return new KakaoPayPayment();
        throw new IllegalArgumentException("지원하지 않는 결제 방식");
    }
}

// 사용
Payment payment = PaymentFactory.createPayment("KAKAOPAY");
payment.process(amount);
```

### **2. 팩토리 메소드 - 문서 생성기**
```java
// 보고서 생성 프레임워크
abstract class ReportGenerator {
    // 템플릿 메소드
    public Report generateReport(Data data) {
        Report report = createReport();  // 팩토리 메소드
        report.setData(data);
        report.format();
        report.validate();
        return report;
    }
    
    // 팩토리 메소드 - 서브클래스에서 구현
    protected abstract Report createReport();
}

class SalesReportGenerator extends ReportGenerator {
    protected Report createReport() {
        return new SalesReport();  // 영업 보고서 생성
    }
}

class FinancialReportGenerator extends ReportGenerator {
    protected Report createReport() {
        return new FinancialReport();  // 재무 보고서 생성
    }
}
```

### **3. 추상 팩토리 - 데이터베이스 연결 팩토리**
```java
// 데이터베이스 벤더별 연결 팩토리
interface DatabaseFactory {
    Connection createConnection();
    Query createQuery();
    Transaction createTransaction();
}

class OracleFactory implements DatabaseFactory {
    public Connection createConnection() {
        return new OracleConnection();
    }
    public Query createQuery() {
        return new OracleQuery();
    }
    public Transaction createTransaction() {
        return new OracleTransaction();
    }
}

class MySQLFactory implements DatabaseFactory {
    public Connection createConnection() {
        return new MySQLConnection();
    }
    public Query createQuery() {
        return new MySQLQuery();
    }
    public Transaction createTransaction() {
        return new MySQLTransaction();
    }
}

// 애플리케이션 설정 기반 팩토리 선택
public class DatabaseFactoryProvider {
    public static DatabaseFactory getFactory() {
        String dbType = Config.get("database.type");
        
        if ("oracle".equals(dbType)) return new OracleFactory();
        if ("mysql".equals(dbType)) return new MySQLFactory();
        if ("postgresql".equals(dbType)) return new PostgreSQLFactory();
        
        throw new RuntimeException("지원하지 않는 데이터베이스");
    }
}
```

## **표로 정리**

| 항목 | 간단 팩토리 | 팩토리 메소드 | 추상 팩토리 |
|------|------------|---------------|-------------|
| **패턴 유형** | 생성 패턴 | 생성 패턴 | 생성 패턴 |
| **주요 목적** | 객체 생성 캡슐화 | 객체 생성 위임 | 관련 객체 패밀리 생성 |
| **적용 시기** | 객체 생성이 간단할 때 | 서브클래스가 객체 생성 방식을 결정할 때 | 연관된 객체들을 함께 생성할 때 |
| **구현 방식** | 조건문 기반 단일 메소드 | 추상 메소드 + 서브클래스 구현 | 인터페이스 + 구체 팩토리 |
| **확장성** | 낮음 (OCP 위반) | 높음 (OCP 준수) | 높음 (OCP 준수) |
| **복잡도** | 낮음 | 중간 | 높음 |
| **실무 예시** | 결제 수단 생성기 | 보고서 생성기 | DB 벤더별 연결 팩토리 |
| **장점** | 구현이 쉬움, 빠른 적용 | 유연성 높음, 확장 쉬움 | 일관성 보장, 제품군 관리 용이 |
| **단점** | 조건문 복잡해질 수 있음 | 클래스 수 증가 | 초기 구현 비용 높음 |

## **실무 적용 시 고려사항**

### **언제 사용하는가?**
- **간단 팩토리**: 프로토타입, 소규모 프로젝트, 생성 로직이 단순할 때
- **팩토리 메소드**: 프레임워크 설계, 플러그인 아키텍처, 확장성이 중요할 때
- **추상 팩토리**: 크로스 플랫폼 지원, 테마/스킨 시스템, DB 벤더 독립성 필요할 때

### **실무 적용 팁**
1. **의존성 주입(DI) 프레임워크와 함께 사용**
   ```java
   @Configuration
   public class AppConfig {
       @Bean
       @ConditionalOnProperty("payment.provider=kakao")
       public PaymentFactory kakaoPaymentFactory() {
           return new KakaoPaymentFactory();
       }
   }
   ```

2. **캐싱과 함께 사용**
   ```java
   public class CachedFactory {
       private static Map<String, Object> cache = new ConcurrentHashMap<>();
       
       public Product getProduct(String key) {
           return cache.computeIfAbsent(key, k -> createProduct(k));
       }
       
       private Product createProduct(String type) {
           // 실제 생성 로직
       }
   }
   ```

3. **실무에서 가장 흔한 사용처**
   - 결제 게이트웨이 생성
   - 리포트/문서 생성기
   - 데이터베이스 연결 관리
   - UI 컴포넌트 팩토리
   - 캐시 클라이언트 생성 (Redis, Memcached)

**핵심 요약**: 팩토리 패턴은 "new"의 사용을 제한하고, 객체 생성 로직을 체계화하여 유지보수성과 확장성을 높이는 기본적이면서도 강력한 패턴이다.
