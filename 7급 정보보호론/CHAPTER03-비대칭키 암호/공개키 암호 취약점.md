

## 1. CPA / CCA의 정체

* **CPA / CCA는 공격이 아니라 안전성 모델이다.**
* 특정 암호가 **어디까지 안전한가**를 이론적으로 정의하는 기준이다.

### 정의

* **CPA (Chosen Plaintext Attack)**
  공격자가 임의의 평문을 선택해 암호문을 얻을 수 있어도 안전해야 한다는 모델이다.
* **CCA (Chosen Ciphertext Attack)**
  공격자가 임의의 암호문을 선택해 복호 결과를 얻을 수 있어도 안전해야 한다는 모델이다.

---

## 2. 공개키 vs 대칭키에서의 CPA / CCA 의미

### 공개키 암호

* 공개키는 **누구나 암호화 가능**하다.
* 구조적으로 **항상 CPA 환경에 노출**된다.
* 따라서 **CPA-secure는 최소 조건**이다.
* 실무에서는 **CCA-secure까지 요구**된다.

예:

* RSA (기본형) → CPA/CCA 모두 취약
* RSA-OAEP → CCA-secure

---

### 대칭키 암호

* 대칭키도 CPA/CCA 모델로 평가된다.
* **암호 알고리즘(AES)** 이 아니라 **운영 모드(mode)** 가 핵심이다.

정확한 표현:

* AES 자체는 **PRP(의사난수 순열)** 이다.
* **AES-GCM, AES-CCM** → CPA/CCA-secure
* **AES-CBC + PKCS#7** → CCA 취약 (Padding Oracle)

즉,

> 대칭키의 CCA 취약점은 암호가 아니라 **운영 방식 문제**이다.

---

## 3. 수학적 구조 vs 운영 모드

### 공개키 암호의 CCA 취약점 원인

* **수학적 동형성**에서 기인한다.

예:

* RSA:
  ( E(m_1) \cdot E(m_2) = E(m_1 \cdot m_2) )

→ 암호문 조작으로 평문 관계 추론 가능
→ CCA 공격 가능

---

### 대칭키 암호의 CCA 취약점 원인

* **운영 모드 + 패딩 방식**에서 발생한다.

예:

* CBC + 패딩 에러 메시지
* 복호 결과에 따라 에러 응답이 달라짐
* 공격자가 복호 오라클을 간접적으로 획득

→ Padding Oracle Attack

---

## 4. MITM의 본질

* **MITM은 암호 알고리즘 문제가 아니다.**
* **프로토콜과 인증 문제이다.**

핵심:

* 키 교환 과정에서 **상대방을 인증하지 않으면** 발생한다.
* 공개키 / 대칭키 여부와 무관하다.

예:

* 대칭키만 사용해도
  → 초기 키 전달 과정에서 MITM 발생 가능
* 해결책
  → 인증서, 디지털 서명, TLS 핸드셰이크

MITM은 **중간자 공격**(Man-In-The-Middle)이다. 공격 방식 자체는 공격자가 **통신 경로에 끼어들어 메시지를 가로채거나 변조**하는 것이다.

그런데 MITM가 발생하는 근본 원인은 **암호 알고리즘 자체가 취약해서가 아니라, 상대방을 인증하지 않아서**이다.
즉, 공격자가 중간에서 끼어들 수 있는 이유가 **누가 누구와 통신하는지 확인할 수 없는 프로토콜 설계**에 있다.

예시로 정리하면:

| 상황                    | 문제      | 설명                                                 |
| --------------------- | ------- | -------------------------------------------------- |
| 단순 암호화만 사용 (AES, RSA) | MITM 가능 | 암호화 자체는 안전하지만, 누가 누구에게 메시지를 보내는지 확인하지 않음           |
| TLS / 공개키 인증서 사용      | MITM 방지 | 인증서를 통해 서버/클라이언트 신원을 검증, 공격자가 중간에서 메시지를 변조하면 검증 실패 |

핵심:

* MITM는 공격 **형태**이고
* 발생 **원인**은 인증이 없거나 불완전한 프로토콜 설계이다.

즉, 암호화만으로는 MITM을 막을 수 없고, **인증과 암호화를 함께 설계해야 안전**하다.

## 5. 공격 / 취약점 비교표 (정리본)

| 구분     | 본질      | 공격 대상    | 원인          | 실무 영향     | 대응              |
| ------ | ------- | -------- | ----------- | --------- | --------------- |
| 타이밍 공격 | 구현 취약점  | 연산 시간    | 비상수 시간 연산   | 키 노출      | 상수시간 구현         |
| 사이드채널  | 구현 취약점  | 전력·EM·캐시 | 물리적 관측      | 키/내부상태 노출 | 하드웨어 보호         |
| CPA    | 이론 모델   | 암호화 오라클  | 공개키 구조      | 기본 요구 조건  | CPA-secure 알고리즘 |
| CCA    | 이론 모델   | 복호 오라클   | 수학적 구조 / 모드 | 평문·키 노출   | OAEP, AEAD      |
| MITM   | 프로토콜 문제(인증) | 통신 채널    | 인증 부재       | 메시지 위조    | TLS, 인증서        |

---

## 6. 한 줄 정리

* **CPA/CCA** → 암호의 이론적 안전성 기준이다.
* **공개키** → 구조적으로 CPA 노출, CCA 대응 필수이다.
* **대칭키** → 취약점은 모드와 패딩 문제이다.
* **MITM** → 암호 문제가 아니라 인증 문제이다.
* **실무 핵심** → 검증된 알고리즘 + 안전한 운영 모드 + 인증이다.
