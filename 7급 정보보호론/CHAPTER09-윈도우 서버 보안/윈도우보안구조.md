
# 1. LSA (Local Security Authority)

## 1-1. 개념

* LSA는 로컬 보안 관리자(Local Security Authority)이다.
* 윈도우에서 사용자 로그인, 인증, 권한 부여를 담당하는 핵심 서비스이다.

---

## 1-2. 역할

1. 사용자 인증 수행
2. 액세스 토큰 발급
3. 정책 검증 및 권한 확인
4. Kerberos, NTLM 같은 인증 프로토콜 처리

---

## 1-3. 특징

* NTOSKRNL(윈도우 커널)과 연결되어 작동
* 로그인 시 비밀번호 검증과 권한 토큰 생성
* 시스템 보안을 위한 최상위 서비스

---

# 2. SAM (Security Account Manager)

## 2-1. 개념

* SAM은 사용자 계정과 패스워드 정보를 저장하는 데이터베이스이다.
* 일반적으로 `C:\Windows\System32\config\SAM` 파일에 존재한다.

---

## 2-2. 역할

1. 로컬 사용자 계정 정보 저장
2. 패스워드 해시 관리(NTLM 해시 등)
3. 사용자 인증 요청 시 LSA에 정보 제공

---

## 2-3. 특징

* 직접 접근은 권한 제한
* 레지스트리 하위 `HKLM\SAM`에도 정보 저장
* 로컬 로그인 계정과 비밀번호를 관리

---

# 3. SRM (Security Reference Monitor)

## 3-1. 개념

* SRM은 윈도우 커널의 보안 정책 집행 모듈이다.
* 모든 접근 요청에 대해 권한 검사 및 접근 제어를 수행한다.

---

## 3-2. 역할

1. 액세스 토큰 검증
2. 파일, 프로세스, 레지스트리 등 객체 접근 허용 여부 결정
3. LSA가 발급한 토큰을 기반으로 접근 권한 판단

---

## 3-3. 특징

* 커널 모드에서 동작
* 시스템의 최종 권한 검사 담당
* 윈도우 보안 아키텍처의 핵심 요소

---

# 4. 세 모듈 관계

| 구성요소 | 역할               | 특징               |
| ---- | ---------------- | ---------------- |
| LSA  | 사용자 인증, 권한 토큰 발급 | OS 로그인/인증 담당     |
| SAM  | 로컬 계정과 비밀번호 저장   | 해시 형태로 안전하게 관리   |
| SRM  | 접근 권한 최종 확인      | 커널 레벨에서 객체 접근 제어 |

---

# 5. 동작 예시

1. 사용자가 로그인 → LSA가 인증 요청
2. LSA가 SAM 데이터베이스에서 계정/패스워드 확인
3. 인증 성공 시 액세스 토큰 생성
4. SRM이 토큰 기반으로 파일·프로세스 접근 허용 여부 판단

---

# 6. 핵심 요약

* LSA: 로그인과 인증 담당
* SAM: 계정과 비밀번호 저장
* SRM: 권한과 접근 제어 담당
* 관계: LSA → SAM(계정 확인) → SRM(권한 검증) 순으로 윈도우 보안 정책 실행
