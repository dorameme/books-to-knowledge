# 1. 클래스 기반 주소 체계 (Classful Addressing)

## 개념

IP 주소를 **A, B, C 클래스**로 미리 정해진 크기대로 나누어 사용하는 방식이다.
네트워크와 호스트의 경계가 **고정**되어 있다.

## 등장 이유

* 인터넷 초창기
* 네트워크 규모 예측이 쉬웠다
* 구현이 단순했다

## 비유

* 정해진 크기의 아파트만 분양한다

  * 소형 / 중형 / 대형 중 하나만 선택 가능

## 특징

* 단순하다
* 네트워크 크기 선택의 자유가 없다
* IP 주소 낭비가 심하다

## 실무

* 현재는 사용하지 않는다
* 시험·이론용 개념이다

---

# 2. 서브네팅 (Subnetting)

## 개념

하나의 클래스 기반 네트워크를 **더 작은 네트워크로 분할**하는 기술이다.
호스트 비트를 일부 빌려 네트워크 비트를 늘린다.

## 등장 이유

* 클래스 기반 주소가 너무 컸다
* 내부 네트워크를 논리적으로 분리할 필요가 생겼다

## 비유

* 하나의 아파트 단지를
* 동 / 층 / 라인 단위로 나눈다

## 특징

* 브로드캐스트 범위를 줄인다
* 보안과 관리가 쉬워진다
* 출발점은 클래스 기반이다

## 실무

* 부서별 네트워크 분리
* VLAN과 함께 사용
* 내부 설계의 기본 기술이다

---

# 3. 슈퍼네팅 (Supernetting)

## 개념

여러 개의 연속된 네트워크를 **하나의 큰 네트워크처럼 묶는 기술**이다.
네트워크 비트를 줄이고 호스트 비트를 늘린다.

## 등장 이유

* 라우팅 테이블이 너무 커졌다
* 라우팅 성능 저하 문제가 발생했다

## 비유

* 여러 개의 작은 아파트 단지를
* 행정상 하나의 대단지로 관리

## 특징

* 라우팅 테이블 크기 감소
* 경로 요약 가능
* 클래스 기반 네트워크를 전제로 한다

## 실무

* ISP, 대규모 네트워크
* 라우팅 최적화 목적

---

# 4. CIDR (Classless Inter-Domain Routing)

## 개념

클래스 개념을 **완전히 제거**하고
`/n` 표기로 네트워크 경계를 자유롭게 정의하는 방식이다.

## 등장 이유

* IP 주소 고갈 문제
* 클래스 기반 구조의 한계
* 서브네팅과 슈퍼네팅을 통합할 필요

## 비유

* “대형·중형·소형 중 고르세요”가 아니라
* “필요한 세대 수만 말하면 맞춰 설계”

## 특징

* 주소 낭비 최소화
* 매우 유연한 네트워크 설계
* 현재 인터넷의 표준이다

## 실무

* 모든 현대 네트워크
* 클라우드, ISP, 기업망 전부 CIDR 사용

# 핵심 비교 표

| 구분      | 클래스 기반 | 서브네팅  | 슈퍼네팅   | CIDR |
| ------- | ------ | ----- | ------ | ---- |
| 클래스 의존  | O      | O     | O      | X    |
| 네트워크 경계 | 고정     | 확장    | 축소     | 자유   |
| 주소 낭비   | 심함     | 감소    | 감소     | 최소   |
| 주요 목적   | 단순성    | 내부 분할 | 라우팅 요약 | 유연성  |
| 실무 사용   | X      | O     | O      | 필수   |

---

# 흐름 한 줄 요약

과거: 클래스 기반 → 낭비 심함    
↓    
서브네팅: 내부에서 쪼개 씀    
↓    
슈퍼네팅: 외부에서는 묶어 보임    
↓       
CIDR: 둘 다 자유롭게 함 (현재)



클래스 기반은 단순했지만 낭비가 컸고,
서브네팅과 슈퍼네팅은 이를 보완했으며,
CIDR은 클래스 자체를 제거한 최종 해법이다.
