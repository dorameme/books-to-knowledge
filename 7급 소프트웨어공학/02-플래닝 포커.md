# Planning Poker: Agile Estimation Technique

## 1. 개요

플래닝 포커는 애자일 소프트웨어 개발에서 사용자 스토리나 작업의 상대적인 규모를 추정하기 위해 사용하는 합의 기반의 기법이다.        
팀 구성원들이 각자 독립적으로 의견을 제시한 후 토론을 거쳐 하나의 수치에 합의하는 과정을 거친다.

## 2. 도입 목적

* **앵커링 효과 방지:** 특정 인물의 의견에 팀 전체가 편향되는 현상을 차단한다.
* **지식 공유:** 작업에 대한 각자의 이해도를 공유하여 잠재적 리스크를 조기 발견한다.
* **합리적 합의:** 팀 전체의 참여를 통해 추정치에 대한 책임감과 신뢰도를 높인다.

---

## 3. 주요 구성 요소

### 피보나치 수열 (Fibonacci Sequence)

추정 점수는 주로  등 피보나치 수열을 변형하여 사용한다.

* **불확실성 반영:** 작업의 규모가 커질수록 숫자의 간격을 넓게 설정하여 불확실성을 표현한다.
* **효율적 의사결정:** 미세한 수치 차이로 인한 소모적인 논쟁을 줄이고 규모의 본질에 집중하게 한다.

### 스토리 포인트 (Story Point)

시간(Hour) 단위가 아닌 추상적인 작업의 규모를 의미한다. 작업의 복잡도, 노력의 양, 위험 요소를 종합적으로 고려하여 결정한다.

---

## 4. 진행 절차

| 단계 | 활동 내용 |
| --- | --- |
| **설명** | 제품 책임자가 사용자 스토리의 목적과 요구사항을 팀원들에게 설명한다. |
| **질의응답** | 개발 팀원들이 구현 방법, 제약 사항, 의존성 등에 대해 자유롭게 질문한다. |
| **개별 투표** | 각자 생각하는 점수의 카드를 선택하여 보이지 않게 내려놓는다. |
| **동시 공개** | 모든 구성원이 동시에 자신의 카드를 공개한다. |
| **의견 조율** | 최고점과 최저점을 낸 인원이 각각의 근거를 논리적으로 설명한다. |
| **합의 도출** | 토론을 바탕으로 점수가 수렴할 때까지 재투표를 반복한다. |

---

## 5. 기대 효과

* **정확도 향상:** 다양한 직군의 관점이 반영되어 단독 추정보다 정확한 결과를 얻는다.
* **팀 정렬:** 요구사항에 대한 팀원들의 이해도를 동일한 수준으로 맞출 수 있다.
* **집중도 유지:** 게임화된 방식을 통해 추정 회의의 지루함을 방지하고 몰입도를 높인다.
