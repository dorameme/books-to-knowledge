

## 1. 접근제어모델이란 무엇인가

접근제어모델은
**“누가(주체) 무엇에(객체) 어떤 권한으로 접근할 수 있는가”를 결정하는 규칙 체계**이다.

보안에서 중요한 이유는
 **침해가 발생했을 때 피해가 어디까지 확산되는지를 결정하기 때문**이다.

---

## 2. 주요 접근제어모델 상세 설명

### 2.1 DAC (Discretionary Access Control)

#### 개념

객체(파일, 리소스)의 **소유자**가 접근 권한을 직접 설정하는 방식이다.

#### 동작 구조

* 사용자 A가 파일을 생성한다
* A가 읽기/쓰기/실행 권한을 다른 사용자에게 부여한다
* 운영체제는 소유자의 결정을 그대로 따른다

#### 특징

* 유연하다
* 사용이 쉽다
* 사용자 판단에 전적으로 의존한다

#### 핵심 문제

 **권한이 사용자 의지에 따라 전파된다**

---

### 2.2 MAC (Mandatory Access Control)

#### 개념

시스템이 정한 **보안 등급과 정책**에 따라 접근을 강제하는 방식이다.

#### 동작 구조

* 주체와 객체에 보안 등급이 있다
* 시스템 정책이 접근 가능 여부를 판단한다
* 사용자는 임의로 권한을 변경할 수 없다

#### 특징

* 매우 강제적이다
* 군사, 정부 시스템에서 사용한다
* 유연성은 낮다

#### 핵심 포인트

 **사람의 실수를 구조적으로 차단한다**

---

### 2.3 RBAC (Role-Based Access Control)

#### 개념

사용자가 아니라 **역할(Role)** 에 권한을 부여하는 방식이다.

#### 동작 구조

* 역할에 권한을 묶는다
* 사용자는 역할만 할당받는다
* 개인별 권한 관리가 사라진다

#### 특징

* 대규모 조직에 적합하다
* 관리가 쉽다
* 권한 오남용을 줄인다

#### 핵심 포인트

 **사람의 판단 범위를 역할 단위로 제한한다**

---

## 3. 접근제어모델 비교 표

| 구분          | DAC   | MAC    | RBAC   |
| ----------- | ----- | ------ | ------ |
| 권한 결정 주체    | 사용자   | 시스템    | 역할     |
| 권한 변경 가능 여부 | 가능    | 불가능    | 제한적    |
| 유연성         | 높음    | 낮음     | 중간     |
| 보안 강도       | 낮음    | 매우 높음  | 높음     |
| 사람 실수 영향    | 매우 큼  | 거의 없음  | 제한적    |
| 멀웨어 확산 위험   | 매우 높음 | 매우 낮음  | 중간     |
| 대표 사용 예     | 개인 PC | 군사 시스템 | 기업 시스템 |

---

## 4. 왜 DAC가 트로이목마·멀웨어에 유독 취약한가

### 핵심 이유 한 줄

 **DAC는 “사용자가 가진 권한 = 프로그램이 가지는 권한” 구조이기 때문이다**

---

### 실제 동작 흐름 (중요)

1. 사용자가 파일을 실행한다
2. 운영체제는 **사용자 권한으로 프로그램을 실행한다**
3. 프로그램이 파일 접근을 시도한다
4. 운영체제는 “이 사용자가 접근 가능함” → 허용한다

 **프로그램이 선한지 악성인지 판단하지 않는다**

---

### 그래서 발생하는 문제

* 트로이목마는 사용자를 속여 실행만 되면 끝이다
* 이후 행동은 모두 “정상 사용자 행위”로 처리된다
* 운영체제는 이를 공격으로 인식하지 않는다

---

## 5. “사람을 속인다”의 정확한 의미

여기서 사람을 속인다는 것은
**접근제어를 우회하는 것이 아니라, 정상 절차를 이용하게 만드는 것**이다.

### 예시

* 무료 프로그램처럼 위장한다
* 문서 파일처럼 보이게 만든다
* 보안 경고를 무시하게 만든다

 사용자가 **자발적으로 실행**한다
 시스템 입장에서는 **정상 동작**이다

---

## 6. 멀웨어는 사람을 속이지 않는 것 아니냐? → 반은 맞고 반은 틀리다

### 구분해야 한다

#### 1️⃣ 초기 침투 단계

* 대부분 사람을 속인다
* 실행 권한을 얻기 위해서다

#### 2️⃣ 실행 이후 단계

* 사람을 속이지 않는다
* 시스템 권한 구조를 그대로 악용한다

 **사람을 속이는 것은 입장권 획득 단계이다**

---

## 7. 접근제어모델별 멀웨어 영향 비교

| 항목        | DAC       | MAC       | RBAC       |
| --------- | --------- | --------- | ---------- |
| 사용자 실행 시  | 즉시 권한 획득  | 정책에 의해 차단 | 역할 범위 내 제한 |
| 권한 전파     | 가능        | 불가능       | 제한         |
| 시스템 파일 접근 | 가능        | 거의 불가     | 역할에 따라 제한  |
| 피해 확산 범위  | 사용자 전체 권한 | 최소화       | 역할 단위      |

---

## 8. 왜 보안에서 “차이”가 발생하는가 정리

보안 차이는
 **신뢰 대상을 어디에 두느냐의 차이**이다

* DAC: 사람을 신뢰한다
* MAC: 시스템 정책만 신뢰한다
* RBAC: 역할만 신뢰한다

멀웨어는
 **사람을 신뢰하는 구조를 가장 잘 이용한다**

---

## 9. 한 문장 요약

DAC가 멀웨어에 취약한 이유는
**“사용자의 권한 판단을 그대로 프로그램에 위임하는 구조”이기 때문이다**
