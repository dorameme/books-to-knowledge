

## 1. 한 줄 정의

| 구분  | 정의                           |
| --- | ---------------------------- |
| 일반화 | 상위 클래스의 개념을 하위 클래스가 **상속**한다 |
| 실체화 | 인터페이스의 **명세를 구현**한다          |

---

## 2. 가장 쉬운 구별 질문

> **“부모가 구현을 가지고 있는가?”**

| 질문 결과            | 관계    |
| ---------------- | ----- |
| 구현을 가진 부모를 물려받는다 | 일반화이다 |
| 구현은 없고 약속만 있다    | 실체화이다 |

---

## 3. 코드로 바로 구별

### 3-1. 일반화 예시 (extends)

```java
class Animal {
    void eat() {}
}

class Dog extends Animal {
}
```

* Animal은 **구현을 가진다**
* Dog는 기능을 그대로 물려받는다
* is-a 관계이다
  → Dog는 Animal이다

→ 일반화이다

---

### 3-2. 실체화 예시 (implements)

```java
interface Flyable {
    void fly();
}

class Bird implements Flyable {
    public void fly() {}
}
```

* Flyable은 **구현이 없다**
* Bird가 실제 동작을 만든다
* 행동 규약을 만족한다

→ 실체화이다

---

## 4. 실생활 비유

### 일반화

* 동물 → 개이다
* 공통 속성과 행동을 물려받는다
* 부모가 실제 능력을 가진다

→ 개념 확장이다

---

### 실체화

* 결제수단 → 카드결제이다
* 결제수단은 방법만 정의한다
* 카드결제가 실제로 수행한다

→ 약속을 현실로 만든다

---

## 5. UML 표기 차이

| 구분  | 일반화       | 실체화         |
| --- | --------- | ----------- |
| 선   | 실선        | 점선          |
| 화살표 | 빈 삼각형     | 빈 삼각형       |
| 대상  | 클래스 → 클래스 | 클래스 → 인터페이스 |
| 의미  | 상속        | 구현          |

---

## 6. 언제 쓰는가

| 상황             | 선택  |
| -------------- | --- |
| 공통 로직이 있다      | 일반화 |
| 구현은 다르고 규칙만 같다 | 실체화 |
| 코드 재사용이 목적이다   | 일반화 |
| 유연성과 확장이 목적이다  | 실체화 |

---

## 7. 절대 헷갈리지 않는 한 문장

* **일반화는 “물려받는다”이다**
* **실체화는 “약속을 지킨다”이다**
