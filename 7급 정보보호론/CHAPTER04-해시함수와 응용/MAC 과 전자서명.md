
##  MAC이 부인방지를 못 하는 이유

### MAC의 전제

* **비밀키를 송신자와 수신자가 공유한다**
* MAC = `MAC(K, 메시지)`

즉,

* 송신자도 K를 안다
* **수신자도 K를 안다**

---

### 문제가 되는 상황 (분쟁)

송신자가 말한다.

> “나는 그 메시지 보낸 적 없다”

수신자가 증거로 내민다.

```
메시지 M
MAC(K, M)
```

### 법적·논리적 문제

* 수신자도 K를 알고 있음
* **수신자가 직접 MAC을 만들어도 구분 불가**

 제3자는
**“이 MAC을 누가 만들었는지 구별할 수 없다”**

 결론
MAC은 **무결성·인증(authentication)** 은 되지만
**부인방지(non-repudiation)** 는 불가능하다.

---

##  전자서명이 부인방지를 가능한 이유

### 전자서명의 전제

* 개인키(private key)는 **서명자만 알고 있다**
* 공개키(public key)는 **모두가 안다**

전자서명 =

```
서명 = Sign(개인키, 메시지)
```

검증 =

```
Verify(공개키, 메시지, 서명)
```

---

### 분쟁 상황

서명자가 말한다.

> “내가 보낸 거 아니다”

수신자 또는 제3자는:

* 서명
* 메시지
* 서명자의 **공개키**

를 제시한다.

### 검증 결과

* 공개키로 검증 성공
* 개인키는 서명자만 알고 있음

 **서명자는 부인할 수 없다**

### 포인트

* 수신자는 개인키가 없음
* 제3자도 개인키가 없음
* **오직 서명자만 서명 생성 가능**

---

##  MAC vs 전자서명 핵심 비교

| 구분        | MAC       | 전자서명         |
| --------- | --------- | ------------ |
| 키 구조      | 대칭키 (공유)  | 비대칭키 (개인/공개) |
| 누가 생성 가능? | 송신자 + 수신자 | 서명자만         |
| 제3자 검증    | 불가능       | 가능           |
| 무결성       | 가능        | 가능           |
| 인증        | 가능        | 가능           |
| **부인방지**  | ❌         | ⭕            |

---

## 4️ 한 문장으로 정리

* **MAC은 “우리 둘 다 키를 안다” → 누가 만들었는지 증명 불가**
* **전자서명은 “나만 개인키를 안다” → 내가 만들었다는 증명 가능**

이 차이 때문에
 **MAC은 부인방지를 할 수 없고, 전자서명은 가능하다.**

이해 안 되는 지점 있으면 거기만 바로 찌르면 된다.
