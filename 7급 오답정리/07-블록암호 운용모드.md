## 블록암호 운용모드

### 1. 블록 암호 운용 모드 개요

블록 암호는 정해진 크기(블록) 단위로 데이터를 처리한다. 하지만 실제 데이터는 블록보다 훨씬 길기 때문에,         
이를 어떤 방식으로 연결하여 암호화할지 결정해야 하는데 이를 운용 모드라고 한다.

### 2. 주요 운용 모드별 특징

#### ① ECB (Electronic CodeBook, 전자 코드북 모드)

* 작동: 각 블록을 아무런 연결 관계없이 독립적으로 암호화한다.
* 암복호화 구조: 암호화 시에는 암호화 함수()를, 복호화 시에는 복호화 함수()를 사용한다. ()
* 특징: 동일한 평문 블록은 항상 동일한 암호문 블록을 만든다. 패턴 노출 위험이 커서 보안성이 가장 낮다.

#### ② CBC (Cipher Block Chaining, 암호 블록 체인 모드)

* 작동: 이전 단계의 암호문 블록을 다음 평문 블록과 XOR한 뒤 암호화한다.
* 암복호화 구조: 평문이 암호화 함수() 내부로 직접 들어가므로, 복호화할 때는 반드시 반대 기능을 하는 복호화 함수()가 필요하다. ()
* 특징: 보안성이 높지만, 암호화 과정이 순차적이라 병렬 처리가 불가능하다.

#### ③ CTR (Counter, 카운터 모드)

* 작동: '비밀키'와 '카운터'를 암호화 함수에 넣어 키 스트림을 생성하고, 이를 평문과 XOR한다.
* 암복호화 구조: 암호화와 복호화 시에 사용하는 함수가 동일한 암호화 함수()다.
* 특징: 병렬 처리가 가능해 속도가 매우 빠르고, 현대 암호 시스템에서 가장 널리 쓰인다.

---

### 3. 암호화와 복호화 함수가 같아지는 이유: 키 스트림과 XOR

가장 헷갈리는 부분인 "왜 어떤 모드는 암복호화 함수가 같고, 어떤 모드는 다른가?"에 대한 해답은 데이터가 암호화 엔진 내부로 직접 들어가는지에 달려 있다.

#### ① 데이터 직접 입력 방식 (ECB, CBC)

이 모드들은 평문 데이터를 암호화 알고리즘()이라는 기계 안에 직접 집어넣어 형태를 비튼다. 찌그러진 데이터를 원래대로 펴려면 당연히 그 반대 방향으로 작동하는 복호화 기계()가 따로 필요하다.

#### ② 키 스트림 방식 (CTR, OFB, CFB)

이 모드들에서 암호화 알고리즘()은 데이터를 직접 만지지 않는다. 대신 '키 스트림(Key Stream)'이라 불리는 무작위 난수 비트 열을 만드는 난수 생성기 역할만 수행한다.

* 키 스트림(Key Stream): 암호화 엔진이 비밀키를 바탕으로 찍어낸 일종의 '난수 복권'이다.
* 암호화: 평문  키 스트림 = 암호문
* 복호화: 암호문  (똑같은) 키 스트림 = 평문

---

### 4. XOR 연산이 핵심인 이유

XOR()은 '자기 자신과 두 번 연산하면 원래대로 돌아오는' 수학적 성질을 갖는다.

1. 동일성:  (암호화)
2. 가역성:  (복호화)

이 성질 덕분에 복호화할 때 복잡한 복호화 함수()를 설계할 필요가 없다. 암호화 때 썼던 암호화 함수()를 한 번 더 돌려서 똑같은 키 스트림()만 얻어낸 뒤, 암호문과 다시 XOR하면 평문이 복구되기 때문이다.

---

### 5. 요약 및 결론

* ECB/CBC는 데이터 본체를 변형시키므로 암복호화 함수가 다르다.
* CTR/OFB/CFB는 암호화 함수를 난수 생성기로만 쓰고, 실제 암호화는 XOR로 처리하므로 암복호화 시 똑같은 암호화 함수를 사용한다.
* 키 스트림 방식은 하드웨어 구현이 단순하고 속도가 빨라 현대 암호화의 주류를 이룬다.

---


### CBC 모드와 CTR/OFB/CFB 모드 모두 XOR 연산을 사용하지만, **XOR가 결합되는 위치와 순서**가 결정적인 차이를 만든다.

---

### 1. CBC 모드: 블록 암호화의 '내부'에 데이터가 들어감

CBC(Cipher Block Chaining) 모드는 평문 블록을 암호화 알고리즘($E$)의 **입력값으로 직접 넣는다.**

* **암호화:** $C_i = E_k(P_i \oplus C_{i-1})$
* 평문을 이전 암호문과 XOR한 뒤, 그 결과물을 **암호화 함수($E$)**에 통과시킨다.


* **복호화:** $P_i = D_k(C_i) \oplus C_{i-1}$
* 암호문($C_i$)을 다시 평문으로 돌리려면 반드시 암호화의 역함수인 **복호화 함수($D$)**를 사용해서 알맹이를 꺼낸 뒤 XOR해야 한다.



즉, 데이터 자체가 암호화 함수의 '재료'로 들어가서 변형되기 때문에, 이를 되돌리려면 반드시 반대 기능을 하는 함수($D$)가 필요하다.

---

### 2. CTR/OFB/CFB 모드: 블록 암호화의 '외부'에서 XOR만 함

이 모드들은 암호화 알고리즘($E$)을 데이터를 직접 변형하는 용도가 아니라, 단지 **키 스트림(난수)을 생성하는 도구**로만 사용한다.

* **암호화:** $C_i = P_i \oplus E_k(Nonce + Counter)$
* 암호화 함수($E$)는 난수를 만드는 데만 쓰이고, 실제 데이터($P_i$)는 그 난수와 **XOR**만 한다.


* **복호화:** $P_i = C_i \oplus E_k(Nonce + Counter)$
* XOR 연산의 특성상($A \oplus B \oplus B = A$), 암호화할 때 썼던 그 **똑같은 난수**를 한 번 더 XOR해주면 평문이 나온다.
* 이때 똑같은 난수를 만들기 위해서는 암호화할 때 썼던 **똑같은 암호화 함수($E$)**를 그대로 사용해야 한다. 복호화 함수($D$)를 쓸 이유가 전혀 없다.



---

### 3. 핵심 차이 요약

| 구분 | CBC 모드 | CTR / OFB / CFB 모드 |
| --- | --- | --- |
| **암호화 함수($E$)의 역할** | 데이터($P$)를 직접 뭉개서 암호문 생성 | XOR할 난수(Key Stream)를 생성 |
| **데이터의 위치** | 암호화 함수 **안쪽**으로 들어감 | 암호화 함수 **바깥쪽**에서 XOR됨 |
| **XOR 시점** | 함수 통과 전(또는 후)에 결합 | 함수가 내뱉은 결과물과 결합 |
| **복호화 시 함수** | 역함수인 **복호화 함수($D$)** 필수 | 동일한 **암호화 함수($E$)** 사용 |

**정리하자면**
CBC는 데이터가 암호화 박스 '안'에 갇히기 때문에 박스를 여는 전용 열쇠(복호화 함수)가 필요하지만, CTR 계열은 데이터가 박스 '밖'에서 박스가 만들어준 난수와 섞이기만 하므로 똑같은 난수 생성기(암호화 함수)만 있으면 된다.
