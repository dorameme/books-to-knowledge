

## 1. 기본 개념

JIT 컴파일러는 인터프리터 방식과 컴파일 방식의 중간 형태이다.         
소스 코드를 한 줄씩 해석만 하는 것이 아니라, 자주 실행되는 코드(핫스팟)를 찾아 **기계어로 변환해 캐시에 저장**한다.       
이후 동일한 코드가 실행되면 다시 해석하지 않고 **컴파일된 기계어를 바로 실행**한다.

---

## 2. 왜 사용하는가

* 인터프리터만 사용하면 실행 속도가 느리다
* 사전 컴파일(AOT)은 환경 의존성과 메모리 사용이 크다

JIT는 **실행 속도와 유연성의 균형**을 맞춘다.

---

## 3. 동작 과정

1. 프로그램은 처음에 인터프리터 방식으로 실행된다
2. 실행 중 반복적으로 호출되는 코드가 감지된다
3. 해당 코드를 JIT 컴파일러가 기계어로 변환한다
4. 변환된 코드는 메모리에 저장된다
5. 이후에는 해석 없이 바로 실행된다

---

## 4. 장점

* 반복 실행 구간에서 실행 속도가 매우 빠르다
* 실행 환경(CPU, OS)에 맞춘 최적화가 가능하다
* 초기 로딩은 빠르다

---

## 5. 단점

* 실행 중 컴파일이 발생하므로 순간적인 오버헤드가 있다
* 메모리 사용량이 증가한다
* 동작이 복잡해 예측이 어렵다

---

## 6. 대표적인 사용 사례

* **Java JVM (HotSpot JIT)**
* **C# CLR**
* **JavaScript 엔진(V8 등)**

특히 Java에서는 바이트코드를 JIT가 네이티브 코드로 변환하여 실행 성능을 크게 향상시킨다.

---

## 7. 한 줄 요약

JIT 컴파일러는 **프로그램 실행 중 자주 쓰이는 코드를 즉시 기계어로 변환해 성능을 높이는 컴파일 방식**이다.
