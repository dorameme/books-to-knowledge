## RST 패킷과 세션 하이재킹 정리

### 1. RST(Reset) 패킷의 정의

RST 패킷은 TCP 통신에서 연결을 강제로 종료하기 위해 사용하는 제어 플래그다. 정상적인 종료 절차인 FIN(Finish)과 달리, 응답을 기다리지 않고 즉시 세션을 파괴하는 특성을 가진다.

* 발생 상황: 존재하지 않는 포트로 접속을 시도할 때, 상대방이 예기치 않게 재부팅되었을 때, 혹은 보안 장비가 부적절한 연결을 강제 차단할 때 발생한다.
* 공격적 활용: 공격자가 가짜 RST 패킷을 주입하여 정상적인 서비스를 중단시키는 TCP Reset 공격(DoS의 일종)에 사용된다.

---

### 2. 세션 하이재킹(Session Hijacking)의 정의

세션 하이재킹은 이미 인증을 마친 사용자(클라이언트)와 서버 사이의 연결을 공격자가 가로채는 행위다.      
공격자는 사용자의 로그인 정보를 알 필요 없이, 이미 성립된 세션의 권한을 그대로 이어받는다.

* 핵심 기술: 패킷 스니핑을 통해 서버와 클라이언트가 주고받는 시퀀스 넘버(Sequence Number)를 알아내는 것이 핵심이다.
* 분류: 네트워크 계층에서 TCP 연결을 가로채는 방식과, 응용 계층에서 쿠키나 세션 ID를 탈취하는 방식으로 나뉜다.

---

### 3. RST 패킷과 세션 하이재킹의 상관관계

네트워크 계층의 세션 하이재킹 과정에서 RST 패킷은 기존 사용자의 연결을 끊어버리는 '밀어내기' 용도로 사용된다.

[공격 단계]

1. 스니핑: 공격자는 클라이언트와 서버 사이의 통신을 엿보며 IP 주소와 시퀀스 넘버를 확인한다.
2. RST 주입: 공격자가 클라이언트에게 가짜 RST 패킷을 보내 클라이언트의 연결을 강제로 종료시킨다.
3. 세션 탈취: 서버는 클라이언트가 끊겼음을 인지하지 못한 상태이므로, 공격자가 알아낸 시퀀스 넘버를 사용해 클라이언트인 척 서버에 데이터를 보낸다.
4. 권한 획득: 서버는 공격자를 정상적인 사용자라고 믿고 명령을 수행한다.

---

### 4. 비교 요약

| 구분 | RST 공격 | 세션 하이재킹 |
| --- | --- | --- |
| 목적 | 서비스 방해(연결 파괴) | 권한 탈취(사용자 사칭) |
| 결과 | 통신 불능 상태 발생 | 공격자가 로그인 세션 장악 |
| RST 역할 | 공격의 주된 도구 | 기존 사용자를 제거하는 수단 |

---

### 5. 방어 대책

* 암호화(SSL/TLS): 데이터가 암호화되면 공격자가 시퀀스 넘버나 세션 ID를 알아내기 어려워진다.
* 시퀀스 넘버 랜덤화: 예측하기 어려운 시퀀스 넘버를 사용하여 패킷 주입 공격을 차단한다.
* 지속적 인증: 중요 요청마다 재인증을 요구하거나 클라이언트의 IP/MAC 주소 변동을 감시한다.
