## 스트림 전송 서비스
데이터를 연속된 흐름(stream)로 보장하며 전달하는 전송 방식이다.

---

## 1. 스트림 전송 서비스 개념

스트림 전송 서비스는
데이터의 경계가 보이지 않게,
마치 물이 흐르듯 연속적인 바이트 흐름으로 전달한다.

* 메시지 단위가 아니다
* 바이트 단위 전송이다

---

## 2. 대표 프로토콜

* TCP가 스트림 전송 서비스를 제공한다

---

## 3. 스트림 전송의 핵심 특징

| 특징    | 의미          |
| ----- | ----------- |
| 연결 지향 | 송수신 연결 후 전송 |
| 순서 보장 | 보낸 순서대로 도착  |
| 신뢰성   | 손실 시 재전송    |
| 경계 없음 | 메시지 구분 안 함  |

---

## 4. 왜 스트림 전송이 필요한가

* 파일 전송
* 웹 페이지 로딩
* 데이터 무결성이 중요한 통신

데이터가 깨지거나 순서가 바뀌면 안 된다.

---

## 5. 스트림 vs 메시지 전송

| 구분      | 스트림    | 메시지    |
| ------- | ------ | ------ |
| 데이터 단위  | 바이트 흐름 | 메시지 단위 |
| 경계      | 없음     | 있음     |
| 대표 프로토콜 | TCP    | UDP    |

---

## 6. 비유

* 스트림 전송: 수도관으로 흐르는 물이다
* 메시지 전송: 박스 단위 택배이다

물은 중간 경계가 없다.

---

## 7. 실무 관점

* HTTP/HTTPS 기본은 TCP 스트림이다
* 애플리케이션이 직접 메시지 경계를 정의해야 한다

---

## 8. 한 줄 요약

스트림 전송 서비스는 데이터를 끊김 없는 바이트 흐름으로 전달하는 신뢰성 전송 방식이다.

---


## 스트림 전송 서비스가 없다면?

 **쪼개는 절차가 없다**고 이해하면 정확하다.

---

## 스트림 전송 서비스가 없다는 의미

스트림 전송 서비스가 없다는 것은
**송신 측이 데이터를 연속적인 흐름(스트림)으로 쪼개서 관리해 주지 않는다는 뜻**이다.

즉,

* 전송 계층이

  * 데이터 분할
  * 순서 보장
  * 재조립
  * 누락 데이터 재전송
    을 **해주지 않는다**는 의미이다.

---

## 그럼 실제로는 어떻게 동작하나

### 1. 전송 단위는 처음부터 메시지 단위이다

* 애플리케이션이 보낸 **한 덩어리 = 한 패킷**이다
* “이건 이어진 데이터다”라는 개념이 없다

### 2. 쪼개지지 않는다

* 크면?

  * 그냥 보내지 못하거나
  * 애플리케이션이 직접 쪼개야 한다

### 3. 받는 쪽도 그대로 받는다

* 순서가 바뀌어도 모른다
* 중간에 빠져도 모른다
* 이어 붙여 주지도 않는다

---

## TCP vs UDP로 보면 더 명확하다

### TCP (스트림 전송 서비스 있음)

* 큰 데이터를 알아서 쪼갠다
* 번호 붙인다
* 순서대로 재조립한다
* 빠지면 다시 요청한다

→ “파일을 흘려보내듯” 전송한다

### UDP (스트림 전송 서비스 없음)

* 보낸 만큼 한 번에 간다
* 쪼개지 않는다
* 순서도 보장하지 않는다
* 재전송도 없다

→ “소포 하나 던지고 끝”이다

---

## 핵심 한 줄 요약

스트림 전송 서비스가 없다는 것은
**전송 계층에서 데이터를 쪼개고 이어 붙이는 절차 자체가 없다는 의미이다.**

그래서 필요한 경우
**애플리케이션이 직접 쪼개고, 번호 붙이고, 맞춰야 한다.**
