# 실수 비교 시 자료형 변환의 원리와 올바른 방법

`float`와 `double`을 비교할 때 정밀도가 더 높은 `double`이 아니라, 정밀도가 낮은 `float`로 형변환하여 비교해야 하는 기술적 이유를 정리한다.

## 1. 정밀도의 차이와 정보의 손실

실수형 자료형은 2진수 부동 소수점 방식으로 숫자를 저장한다. 이 과정에서 무한 소수가 발생하면 정해진 비트 수만큼만 저장하고 나머지는 버린다.

* **float (4바이트):** 약 7자리의 정밀도를 가진다.
* **double (8바이트):** 약 15~17자리의 정밀도를 가진다.

똑같은 0.1을 저장하더라도 `float`는 `double`보다 더 빨리 정보를 잃어버리며, 이로 인해 두 자료형이 실질적으로 저장하고 있는 값에는 미세한 차이가 발생한다.

## 2. 왜 정밀도가 낮은 쪽에 맞춰야 하는가?

### 정보 복구의 불가능성

`float`를 `double`로 변환(Up-casting)한다고 해서 이미 소실된 정보가 복구되지 않는다.      
`float`가 가진 오차까지 그대로 `double`로 옮겨갈 뿐이다. 이때 원래부터 정밀했던 `double` 값과 비교하면 소수점 깊은 곳에서 반드시 차이가 발생한다.

### 비교 기준의 통일

비교의 본질은 "두 변수가 같은 대상을 나타내는가"를 확인하는 것이다.         
`float`로 형변환(Down-casting)하는 것은 `double`이 가진 정밀한 부분을 `float` 수준으로 깎아내는 작업이다.      
이렇게 하면 두 변수 모두 동일한 수준의 오차를 가진 상태가 되어 공정한 비교가 가능해진다.

## 3. 비유를 통한 이해: 해상도 비교

* **double:** 4K 고화질 사진
* **float:** 저화질 썸네일 사진

저화질 사진을 강제로 4K 크기로 늘려서 원본 4K 사진과 비교하면, 깨진 픽셀 때문에 두 사진은 서로 다르다고 판정된다.        
하지만 4K 사진을 저화질 크기로 줄여서 비교하면 두 사진이 같은 장면임을 확인할 수 있다.       
즉, 정보가 적은 쪽의 "눈높이"에 맞춰야 데이터의 일치 여부를 논리적으로 판단할 수 있다.

## 4. 코드 구현 예시

```cpp
float  f = 0.1f;
double d = 0.1;

// 잘못된 방법: d 기준 비교 (자동으로 f가 double이 됨)
if (f == d) { 
    // f의 오차가 도드라져 보이므로 false가 발생한다.
}

// 올바른 방법: f 기준 비교 (d의 정밀도를 낮춤)
if (f == (float)d) {
    // 같은 정밀도 수준에서 비교하므로 true가 발생한다.
}

```

## 5. 실무적인 권장 사항

가장 권장되는 방식은 직접적인 비교(`==`) 대신 두 값의 차이가 허용 오차(Epsilon) 이내인지 확인하는 것이다.

```cpp
if (abs(f - d) < 1e-7) {
    // 두 값의 차이가 매우 작으므로 같다고 간주한다.
}

```
