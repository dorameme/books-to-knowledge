## 테스트 스텁과 테스트 드라이버
테스트 스텁(Stub)과 테스트 드라이버(Driver)는 소프트웨어 통합 테스트 시 아직 개발되지 않은 모듈을 대신하기 위해 만드는 가짜 모듈(Dummy Module)이다.       


---

### **1. 테스트 스텁 (Test Stub)**

* **정의:** 테스트 대상 모듈이 호출하는 **하위 모듈**을 일시적으로 대체하는 프로그램이다.
* **주 사용처:** 하향식(Top-Down) 통합 테스트에서 사용한다.
* **역할:** 상위 모듈이 정상적으로 동작하는지 확인하기 위해, 하위 모듈로부터 가짜 결과값을 반환해 주는 역할을 한다.
* **비유:** 요리사(상위 모듈)가 재료를 요청했는데 아직 재료가 준비되지 않아, 가짜 재료(스텁)를 주어 요리 과정만 테스트하는 것과 같다.

### **2. 테스트 드라이버 (Test Driver)**

* **정의:** 테스트 대상 모듈을 호출하는 **상위 모듈**을 일시적으로 대체하는 프로그램이다.
* **주 사용처:** 상향식(Bottom-Up) 통합 테스트에서 사용한다.
* **역할:** 테스트 대상인 하위 모듈에 적절한 입력값을 넘겨주고 실행시켜 보는 시험용 제어 도구이다.
* **비유:** 완성된 엔진(하위 모듈)을 테스트하기 위해 아직 만들어지지 않은 차체(상위 모듈) 대신 임시 가동 장치(드라이버)에 연결해 시동을 걸어보는 것과 같다.

---

### **3. 주요 차이점 요약**

| 구분 | 테스트 스텁 (Stub) | 테스트 드라이버 (Driver) |
| --- | --- | --- |
| **방향** | **하향식** (Top-Down) | **상향식** (Bottom-Up) |
| **대체 대상** | 호출되는 하위 모듈 (피호출자) | 호출하는 상위 모듈 (호출자) |
| **핵심 역할** | 가짜 응답(Return) 제공 | 입력값 전달 및 실행 제어 |
| **복잡도** | 단순한 값 반환 위주라 비교적 단순하다 | 입력값 설정과 결과 확인 로직이 포함되어 더 복잡할 수 있다 |

---

### **4. 테스트 하네스 (Test Harness)**

스텁과 드라이버를 포함하여 테스트를 실행하기 위해 필요한 모든 도구와 데이터를 통틀어 **테스트 하네스**라고 부른다.       
이는 실제 운영 환경이 갖춰지지 않은 상태에서 소프트웨어의 각 부분을 독립적으로 검증할 수 있게 해주는 필수 환경이다.
